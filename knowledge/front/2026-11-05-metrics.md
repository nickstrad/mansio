# Metric catalog and message codes (agentd, RI-11)

Release It O1–O3. `GET /metrics` on the lifecycle listener (`health_listen`; without one, the query listener)
serves the Prometheus text format (0.0.4) from `internal/metrics`, a dependency-free exposition: every family
pulls from a component's own counters at scrape time. **No thresholds in code** — alert rules belong in the
monitoring config. Families marked *CP-1* have adapters in `cmd/agentd/metrics.go`, tested in
`TestDependencyMetricsAndCodes`, and are registered once the control-plane wiring (CP-1) builds the S3 store,
breakers, vactor host and owner table (see the "CP-1 wiring point" comment in `newAgent`).

Outcome classes (same six for every integration point, `front.OutcomeClass`): `ok`; `app_error` (the
dependency answered no: bad request, ticket, wrong owner, fenced, statement rejected or too slow, aborted);
`timeout` (no answer by the deadline, nothing changed); `refused` (shed, unavailable; nothing ran); `5xx`
(internal / transient system failure); `ambiguous` (expired write that may have committed).

## Shed Retry-After (RI-10's deferred estimate)

An admission `shed` now carries a hint: `(VM queue + 1) / completions in the last whole second`, so
`Retry-After = max(1 s floor, hint)`, capped at 60 s. With no completions measured, the floor applies.
