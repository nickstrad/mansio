# 2026-11-05 — the stateless edge (CP-7): design, wire behavior, overhead

Code: `internal/edge` (+ `edgetest`), `cmd/edge`, `configs/edge/`; agentd gained a `tls` section for its query
listener; frontbench gained `-ca`, `-proto h2` and sends `X-Timeout-Ms`. Design source: option 4 §3.6
(`/Users/nick/Software/ts-db/docs/architecture/scale-out-direct-actors.md`). Scripts:
[2026-11-05-edge/bench.sh](2026-11-05-edge/bench.sh), [flood.sh](2026-11-05-edge/flood.sh).

## What it does

```
client ─TLS(h2/h1)─► edge ── rate limit (miss only) → verify ticket → route on vm → bulkhead + breaker ─TLS(h2, private CA)─► agentd /v1/query
```

1. Only `POST /v1/query`; draining → `shed`. `X-Timeout-Ms` is validated as the agent does (else `bad_request`),
   capped at `max_timeout`; no header → `default_timeout`.
2. **Ticket filter.** A verified-ticket cache hit (≈ 32 ns) costs nothing more. A miss is charged one token in a
   per-source bucket (client IP; IPv6 per /64; default 20/s, burst 50, 100k sources, a shared overflow bucket
   when full, idle buckets swept at most once per second), then needs one of `verify_slots` (default
   2 × GOMAXPROCS). Empty bucket → `shed` with `Retry-After` = time to the next token; no slot → `shed` at once.
   Then the full verify (≈ 26 µs) checks framing, signature, claims, time window and `max_ticket_ttl` for
   whichever VM the ticket names. Failure → `ticket_invalid` (401). **No agent is contacted for a bad ticket.**
   The agent still verifies audience, database, permission and epoch itself.
3. **Route** on the `vm` claim through `edge.Resolver` (now `StaticRoutes` from `agents` in the config). Unknown
   VM → `wrong_owner` (421: re-resolve).
4. **Per agent:** a bulkhead (`agent_in_flight`, default 4096; full → `shed`) and a breaker (RI §P defaults,
   `agent_breaker`). **Only transport failures count**: an agent that answers anything, even `unavailable` or
   `internal`, is reachable, so an agent's own S3 outage never stops its warm traffic at the edge (RI C5).
   Breaker open → `unavailable` with `Retry-After` = time to half-open, no dial.
5. **Forward** the body (read first, ≤ `max_body`, so slow clients never hold an agent connection) with the
   client's `Authorization`, `X-Forwarded-For`, and `X-Timeout-Ms` shrunk to the time left (RI T4). The upstream
   ctx ends at deadline + `reply_grace`: the agent answers `expired` itself at the deadline. Errors:
   - nothing written (dial refused, TLS failure) → `unavailable` (503, nothing ran);
   - written, no answer (reset, stuck past deadline + grace) → `expired` with `"ambiguous": true` (504; retry a
     write with the same `request_id`).
6. **Relay** the agent's answer unchanged: status, body (so `request_id`, `duplicate`, `retry_after_ms`), and an
   allowlist of headers (`Content-Type`, `Retry-After`, `WWW-Authenticate`, `Cache-Control`).

No retries at the edge (RI R1: the client is the one retry layer). Edge-made answers use the agent's wire
format (`front.Response`, `front.Spec` statuses and Retry-After floors).

**TLS.** Without `-dev`, the client listener needs `tls` (cert/key; h2 + h1 by ALPN) and every agent URL must be
`https`; `agent_tls.ca_file` is the private CA (default system roots), `agent_tls.server_name` optionally pins
one shared agent name. A CA file with only `http` agents is refused. agentd: a `tls` section makes the query
listener HTTPS (h2 + h1); a non-loopback `listen` without `tls` is refused without `-dev`.

**Keys.** As agentd (CP-5): `keys_file` (static) or `keys_url` (controld's `GET /v1/keys`, fetched every
`keys_refresh` by the shared `internal/keyfetch`, `keys_file` as the cache; plain-HTTP `keys_url` needs `-dev`).
Metrics `edge_ticket_keys`, `edge_keys_fetch_failures_total`, `edge_keys_age_seconds`; events
`EDGE.KEYS_UPDATED|KEYS_FETCH_FAILED|KEYS_FETCH_OK`. A rotated-out key revokes its cached tickets at once.
`cmd/edge` `TestKeysURLRotation` covers it.

**What the edge does not cover from CP-5's deferrals.** The edge proxies only the agents' `/v1/query`. TLS for
controld's `/v1/resolve` and `/v1/keys`, and rate limiting of unknown API key ids at resolve, are still open: put
`/v1/resolve` behind the edge (a second route class with its own per-source bucket charged on unknown key ids) or
give controld the same `tlsx.ServerConfig` + `SourceLimiter`. Both building blocks are reusable as is.

**Lifecycle.** `health_listen` (required, own listener, RI B4): `/livez`, `/readyz` (503 once draining; never
for an agent outage), `/metrics`. Shutdown: drain (shed new, finish in-flight within `drain_timeout`), then close
the lifecycle listener, all inside `shutdown_budget`; a cut drain exits 1 with a log ID.

## Overhead (manual, 2026-11-05)

Machine: Apple M5 Max, 18 cores, macOS; frontbench, edge and agentd all on the one host over loopback, so the
edge competes with both for CPU. agentd static mode, 16 seeded databases, point reads (`w=0`) or 20 % inserts
(`w=0.2`), closed loop, 2 s warmup + 8 s (conc 64) or 5 s (conc 4). Default configs (ticket cache on). Command:
[bench.sh](2026-11-05-edge/bench.sh) (`CONC=4 DUR=5s` for the low-load rows). Second conc-64 run shown (the first
had one noisy tail: edge plain w=0.2 p99.9 49 ms, not reproduced).

**Latency at low load (conc 4): the edge adds ~70 µs plain, ~110–135 µs TLS at p50.**

| plain h1, w=0 | 37,356 | 22,543 | 83 / 312 | 156 / 411 | +73 µs |
| plain h1, w=0.2 | 29,850 | 20,854 | 100 / 419 | 162 / 473 | +62 µs |
| TLS h2, w=0 | 21,064 | 13,075 | 166 / 510 | 274 / 663 | +108 µs |
| TLS h2, w=0.2 | 20,749 | 12,162 | 154 / 536 | 289 / 733 | +135 µs |

| conc 64 | direct ok/s | edge ok/s | direct p50 / p99 µs | edge p50 / p99 µs |
|---|---|---|---|---|
| plain h1, w=0 | 51,769 | 32,109 (62 %) | 992 / 4,137 | 1,714 / 5,623 |
| plain h1, w=0.2 | 52,503 | 31,037 (59 %) | 940 / 5,055 | 1,741 / 6,289 |
| TLS h2, w=0 | 23,014 | 15,107 (66 %) | 2,750 / 4,527 | 4,224 / 6,803 |
| TLS h2, w=0.2 | 22,414 | 15,020 (67 %) | 2,816 / 4,658 | 4,224 / 6,865 |

Reading: on one shared host the edge costs ~35–40 % of peak throughput, which is the price of a second HTTP
server on the same cores, not a property of a separate edge tier; per request it is one loopback HTTP round trip
(~60–135 µs). TLS h2 tops out lower than plain h1 for direct traffic too: Go's h2 client puts all 64 streams on
one connection per hop. Ticket hit rate: 566,396 hits / 36 misses (plain), 287,385 / 34 (TLS): one verify per
ticket per edge.

Micro (`go test -bench BenchmarkTicketFilter ./internal/edge`): cache hit 31.7 ns, 0 allocs; full verify
25.9 µs; forged signature 25.4 µs; garbage (fails framing) 32.6 ns; limiter charge 17.1 ns, 0 allocs.

**Flood, live** ([flood.sh](2026-11-05-edge/flood.sh), TLS both hops): valid frontbench at conc 16 alone
14,287 ok/s p99 2.0 ms; with a concurrent forged-ticket frontbench (conc 64, another issuer key) **from the same
IP**: valid 12,981 ok/s (91 %) p99 2.3 ms, all `ok`. The flood sent 297,818 requests in ~11 s; **180 were
verified** (burst 50 + 20/s), 297,638 shed. The 9 % drop is the flood's HTTP handling on shared cores, not
verifies.

## Decisions

- **Edge verifies, agent verifies again.** The edge cannot check audience/db/perm/epoch without agent state; it
  filters cost, the agent decides. A ticket's vm claim is trusted for routing only after the signature check.
- **Rate limit misses only, per source.** Valid clients reuse tickets (one miss per ticket TTL per edge), so a
  low per-IP rate is invisible to them. Cost: a client behind a NAT shared with a flooder cannot get a *new*
  ticket verified until the bucket refills (cached ones keep working). Behind an L4 load balancer the source is
  the LB unless it preserves client IPs (PROXY protocol / DSR); X-Forwarded-For is not trusted. Revisit when the
  edge is deployed.
- **Breaker counts transport failures only**, not agent 5xx (see above). A slow-but-answering agent is the
  agent's admission problem, not the edge's.
- **Unknown VM → `wrong_owner`** (the client re-resolves; the locator knows the current VM).
- **Bodies are buffered** (≤ 1 MiB) before an agent slot is taken: slow clients cannot hold agent connections.
- **Agent listener off loopback needs TLS** (or `-dev`): agents stay private and authenticated.

## Deferred

- Resolver from controld's VM registry (poll/push) — the `edge.Resolver` seam; `StaticRoutes` now.
- mTLS edge → agent (the agent does not authenticate the edge; tickets are the authorization).
- Admin controls for the edge (breaker trip/reset per agent) and a shared cmd helper package (reporter, log
  opening, lifecycle server) — agentd, controld and edge now each carry a copy (CP-4 deferred the same).
- Edge running on separate hosts from agents and clients: the numbers above are one-host.
- CORS for browsers (option 4 §6) — not needed until browsers call the edge directly.
