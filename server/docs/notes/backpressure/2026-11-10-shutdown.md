# Shutdown: four small gaps closed (B5, 2026-11-10)

| Gap | Change | Code | Test |
|---|---|---|---|
| The edge failed `/readyz` and closed its listener in consecutive statements | `drain_delay` (default 0): fail readiness, keep serving for the delay, then drain. `drain_delay + drain_timeout <= shutdown_budget` | `cmd/edge/main.go`, `config.go` | `TestDrainDelayServesWhileNotReady` |
| controld never changed readiness at shutdown | `drain_delay` (default 0, below `shutdown_budget`): `/readyz` answers 503 `stopping` while the API still serves | `cmd/controld/serve.go`, `api.go` | `TestShutdownDrainDelayAndBudget` |
| controld did not close connections when its budget passed | `http.Server.Close` after a failed `Shutdown` | `cmd/controld/serve.go` | same test: a call stuck sending its body is cut at the budget |
| A passivation's leftover-WAL snapshot ran from `context.Background()` | it runs under the passivation's context (at shutdown, the shutdown budget), still capped by `WriteBackTimeout` | `internal/vactor/writeback.go` `closedCopy` | `TestLeftoverWALSnapshotEndsWithThePassivationsContext` |
| S3 `LIST` could not be stopped by a deadline (minio's one-page call takes no context) | the attempt stops waiting when its context ends; the abandoned request ends at the transport's response-header timeout | `internal/objstore/list.go` | `TestListStopsAtItsDeadlines` |

`drain_delay` defaults to 0 so nothing changes until an operator sets it: set it to at least the load
balancer's readiness poll interval. Side effect of the LIST change: a listing page slower than `OpTimeout` is
now a timed-out attempt that retries (before it simply ran on), so tooling that lists very large prefixes on a
slow store may need a larger `op_timeout`.
